Lesson 1 · 8 minutes

Arabic may cost more.
UTF-8 is not the bill.

For a public explanation and a credible budget, separate three layers: the characters people read, the bytes computers store, and the tokens an LLM API usually charges for.

The accurate headline: Arabic can cost more for comparable meaning when the chosen model’s tokenizer produces more Arabic tokens than English tokens. It is not universally true, and it is not because an API has a price per UTF-8 byte.

Three different counts

CharactersA and م are each one Unicode character.
UTF-8 bytesA is one byte (41). م is two bytes (D9 85).
TokensThe model-specific units sent to, and typically billed by, the API.

UTF-8 affects the byte stream the tokenizer receives. A byte-pair tokenizer then uses its learned vocabulary to combine byte sequences into tokens. If it learned useful Arabic pieces, it can combine them efficiently; if not, it may produce many smaller pieces. That learned vocabulary, not UTF-8 alone, creates the cost difference.

OpenAI’s tiktoken documentation describes BPE as a lossless compression of bytes into common subwords. Its token-counting cookbook notes that API usage is priced by token and different models use different encodings.

What actually gets priced

For a request, use the provider’s reported counts. A general budget is:

request cost = (input tokens × input rate + output tokens × output rate) ÷ 1,000,000

Include cached-input or tool/reasoning categories only if your provider reports and prices them separately. Use the model’s current price page rather than hard-coding a rate in public material.

Measure, then compare

Take paired prompts that request the same task, such as an English and Arabic version of a support reply. Count each with the exact model tokenizer, then send representative traffic and use the API response’s usage fields as the production truth.

For each language and request type, record median and 95th-percentile input and output tokens. Budget monthly cost from those measurements. A useful presentation metric is tokens per completed task, not tokens per character or cost per byte.

Important distinction: JSON requests are transmitted as UTF-8 bytes, which can affect bandwidth or a different service’s byte-based limit. That is separate from an LLM provider’s token invoice.
