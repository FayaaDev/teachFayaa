Quick reference

Token Costs, Not Byte Costs

CharacterWhat a reader sees, such as م or A.
UTF-8 byteHow a character is encoded for storage or transport. ASCII A uses 1 byte; Arabic م uses 2.
TokenA model-specific piece of text, assigned an integer by its tokenizer. This is normally what an LLM API bills.

The causal chain

Text → UTF-8 bytes → tokenizer merges/splits byte sequences → tokens → API price.

UTF-8 makes Arabic text occupy more bytes than ASCII English, but bytes do not determine the number of tokens. A tokenizer’s vocabulary and merges determine it. The same text can tokenize differently under different models.

Budget formula

cost = (input_tokens × input_rate + cached_input_tokens × cached_rate + output_tokens × output_rate) ÷ 1,000,000

Rates are the provider’s listed price per million tokens. Multiply the result by requests per period. Measure each language and request type separately; do not translate a character count into a budget.

Public-safe explanation

“Arabic is not automatically charged per byte. It may cost more for the same intended message when this model’s tokenizer needs more tokens to represent Arabic. We verify that with the model’s tokenizer and price the tokens.”
