Read the gap, not one number

Your tangible win: diagnose a model from training and validation results without treating accuracy as a verdict.

What the two numbers mean

Training accuracy is the fraction of correct predictions on examples used to fit the model. Validation accuracy is the fraction correct on held-out examples that were not used to fit it. Validation performance estimates how the model may generalize to new, similar data.

Accuracy = correct predictions ÷ all predictions. It is useful only when the validation set represents the deployment population and the cost of mistakes and class balance do not make accuracy misleading.
TrainingValidationFirst interpretation
97%78%Large gap: the model learned training-specific patterns. Suspect overfitting (high variance).
62%61%Both weak and close: the model cannot express enough useful pattern. Suspect underfitting (high bias).
91%89%Small gap and strong validation result: promising, subject to the correct metric, baseline, and operational requirements.

There is no universal “bad gap” or “good accuracy.” Compare against a baseline, the business cost of false positives versus false negatives, and the performance needed in production. A fraud detector that is 99% accurate can still be useless if it misses nearly all rare fraud.

Underfitting versus overfitting

UnderfittingOverfitting
Model behaviourToo simple to learn the important signal.Fits training noise or accidental detail.
Typical numbersTraining and validation both poor, with a small gap.Training very strong; validation much weaker.
Useful next moveAdd credible features, increase model capacity, or reduce excessive regularization.Get more representative data, simplify/regularize, limit tree depth, or use an appropriate ensemble.

These are hypotheses, not automatic conclusions. First check that the data split is valid and no leakage, distribution shift, or label error is distorting the comparison.

What is a decision tree?

A decision tree is a supervised model that predicts through a chain of simple feature tests. For example: amount > 4,000 SAR? → yes; new device? → yes; → review. Each internal node tests a feature; each leaf returns a class or numeric prediction.

It can represent threshold-like and interacting rules, and its individual paths are easy to inspect. A deep single tree can be unstable: small changes in training data may produce a very different tree. That is why random forests use many randomized trees and average them.

Source: scikit-learn’s Decision Trees guide describes trees as supervised classification/regression models that learn simple decision rules and notes their instability; its Ensemble guide explains bagging and boosting.

Bagging and boosting

BaggingBoosting
DefinitionTrain multiple versions of a base model independently on randomized samples, then aggregate their predictions.Train weak models sequentially; each later model emphasizes errors made earlier, then combine them.
Main useReduce variance and stabilize an overfit-prone learner, especially deep trees.Build a more accurate model from many simple learners when sequential training and careful tuning are acceptable.
Tree exampleRandom forest: bootstrap samples + feature randomness + averaged/voted trees.Gradient boosting: a new small tree learns what the current ensemble still gets wrong.
Memory testIndependent → aggregate → variance.Sequential → correct → residual error.
When should you use which? Start with a single, interpretable tree if a rule path is required. Use bagging/random forest when a deep tree’s validation gap indicates instability. Consider boosting when you need stronger predictive performance and can validate/tune carefully. Do not choose an ensemble before confirming the target, data quality, metric, and latency budget.
