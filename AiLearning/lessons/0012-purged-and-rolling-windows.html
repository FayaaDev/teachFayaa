Purged and rolling windows

Your tangible win: recognise when a simple expanding window still leaks information across the validation boundary.

The extra rule

Even with forward-only splits, a record that is too close to the validation start can still leak if the model uses features that look backward (lags, rolling statistics). A purged window removes a gap between train and validation. A rolling window keeps training size fixed by dropping the oldest data.

Memory rule: if the feature window can “see” into the validation period, add a purge gap or switch to rolling.
