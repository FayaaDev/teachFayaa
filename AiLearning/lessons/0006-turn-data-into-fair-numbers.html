Turn categories into numbers—without inventing an order

Your tangible win: recognize when to encode categories and when to scale numbers before a distance-based model.

Models need numbers

A data table can contain numbers and words:

CustomerCityMonthly spend
ARiyadh500 SAR
BJeddah900 SAR
CDammam300 SAR

Most models need numeric input. Encoding converts a category such as a city name into numbers.

One-hot encoding: one column per category

For categories with no natural order, use one-hot encoding. Make one column for each possible category. Put 1 in the matching column and 0 in the others.

CityRiyadhJeddahDammam
Riyadh100
Jeddah010

Do not turn city names into 1, 2, and 3 unless those numbers genuinely mean order. Otherwise a model may incorrectly treat city 3 as “more” than city 1.

Memory rule: no real order → separate 0/1 columns.

Scaling: stop big numbers from shouting

Suppose a model compares distance using:

  • Monthly spend: 0 to 100,000 SAR
  • App visits: 0 to 50

Without scaling, monthly spend can dominate the distance simply because its numbers are larger. Scaling changes numeric features to comparable ranges. It does not decide which feature matters most; it prevents measurement units from deciding by accident.

Distance-based methods such as k-NN, k-means, and many SVMs need a scaling check. A decision tree usually does not depend on feature scale in the same way because it asks threshold questions such as “spend > 500?”
