Count × precision = storage

Back to lesson 01
Approximate weight GB = billions of parameters × average bits/weight ÷ 8.
27 × 2.9 ÷ 8 ≈ 9.8 GB.

Use an effective average that accounts for the quantization scheme, not just the digit in its name. File size and rounded parameter counts introduce approximation.

Working glossary

Parameter
A numerical value adjusted during training. “27B” means about 27 billion parameters.
Weight
A learned numerical coefficient. Most parameters are weights; use weight count as the practical shorthand for this lesson's estimate.
Quantization
Representing numerical values at reduced precision, saving storage with a possible quality trade-off.
Bits per weight (bpw)
Average storage bits used for each weight. Mixed precision and supporting scales mean this can be fractional.
Checkpoint
A particular saved set of model parameters. A fine-tune can produce a different checkpoint with the same parameter count.
GGUF
A model file format used by runtimes such as llama.cpp. Q4_K_M and UD-Q2_K_XL name quantization presets, not model identities.
GB / GiB
GB = 1,000,000,000 bytes; GiB = 1,073,741,824 bytes. Thus 9.83 GB ≈ 9.15 GiB.
RAM / VRAM
System working memory / GPU working memory. Some devices share a unified memory pool: do not count that pool twice.
Context / KV cache
Context is the tokens considered in generation. A KV cache stores attention calculations for reuse; its memory needs depend on model and settings.

Before choosing a download

  1. Identify the model family, version, checkpoint, and parameter count.
  2. Check the actual download size and quantization format.
  3. Budget loaded weights, cache/state, and buffers against available memory.
  4. Check runtime and hardware support. Partial CPU offloading may fit but changes speed.
  5. Compare quality on your task. More parameters or more bits alone do not establish the best model.
